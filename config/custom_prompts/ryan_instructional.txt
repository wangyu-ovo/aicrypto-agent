## Mandatory Confidentiality Analysis (Step 0 - before any Action)

Every CTF cryptography challenge is fundamentally a Confidentiality breach: unauthorized disclosure of a value the system was designed to protect. Before any Action, your `### Reasoning` MUST begin with these four subsections, in this exact order, every iteration:

**1. What needs to be protected?**
Name the specific value whose confidentiality you must breach to recover the flag. Examples: "the plaintext message m, which decodes to the flag bytes"; "one of the prime factors p, q of n"; "the private exponent d". Be precise: identify the single secret that, if recovered, makes the flag immediate.

**2. How much protection is needed?**
Identify the cryptographic primitive and parameters providing that protection. Examples: "RSA-1024 encryption"; "AES-128 in CBC mode"; "modular exponentiation with 2048-bit modulus, security resting on the integer factorisation problem". State briefly what would normally make this protection hold for a properly-parameterised system.

**3. For how long is the protection needed?**
For a CTF the answer is typically "until the flag is recovered." Note any time-limited properties of the system that an attacker can exploit (nonce reuse, ephemeral keys, parameters reused across sessions, exponents reused across messages). If no such time-limited weakness applies, say so.

**4. Which threat to Confidentiality applies?**
Pick the most relevant from the four threat types:
- **Exposure**: sensitive data directly released to an unauthorized entity (the public artifacts already contain enough information to derive the secret)
- **Interception**: directly accessing data in transit between authorized sources and destinations (relevant for dynamic challenges with a server)
- **Inference**: indirectly accessing the secret by reasoning from characteristics or by-products of communications (timing oracles, error oracles, padding oracles)
- **Intrusion**: circumventing the system's security protections by exploiting algorithmic flaws in the cryptographic implementation itself (the most common case for static CTF crypto)
Then state the specific structural weakness in the public information that realises the chosen threat (e.g. "Intrusion: same modulus n with two coprime exponents e1, e2 - extended Euclidean algorithm recovers m without breaking the underlying RSA hard problem").

Only after these four subsections may you write the prose analysis and choose an Action. Do not skip the Confidentiality Analysis even on iteration 1 (where it should be most thorough) or on the verification iteration (where it should restate why the recovered value matches the protected target).
